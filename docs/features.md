# 功能设计

portsnap 面向本机端口冲突和进程归属排查。它读取操作系统已经记录的端点信息，不向远程主机发送探测流量。

| 功能 | 解决的问题 | 核心设计 |
| --- | --- | --- |
| 指定端口查询 | 找到某个本地端口关联的进程和连接 | 按本地端口过滤，保留可见的 TCP 状态和 UDP 端点 |
| 监听列表 | 查看服务正在监听或绑定哪些端点 | TCP 只保留 LISTEN，UDP 保留绑定端点 |
| 协议与地址族过滤 | 区分相同端口号上的 TCP/UDP 和 IPv4/IPv6 服务 | 在采集和结果整理时应用查询条件，终止复查保持相同范围 |
| 多进程归属 | 一个监听端点被多个进程共同持有 | 一个端点对应多个 owner，并按 PID 去重 |
| 进程详情 | 区分同名程序及其启动方式和运行用户 | 显式请求后按身份采集，字段独立返回并说明缺失原因 |
| 完整性报告 | 避免把不可读或不可见的数据当作不存在 | 同时表达报告完整性、记录归属状态和诊断原因 |
| 终端展示 | 快速阅读地址、状态和进程信息 | 动态地址列宽、明确的 IPv6 格式和逐进程展示 |
| JSON 输出与诊断代码 | 供脚本消费查询结果并分类处理异常 | 一个带版本号的对象，诊断具有稳定 code，数据与终端诊断分流 |
| 交互式终止 | 处理已确认的占用进程 | 稳定进程引用、逐项确认、归属复查和退出验证 |

## 指定端口查询

```bash
portsnap 8080 3000
```

端口范围为 1–65535，可以一次提供多个。默认每个端口号同时用于 TCP/UDP 和 IPv4/IPv6 查询，因此同一个端口号可能对应多个不同地址、协议或进程。

过滤条件只匹配本地端口，远程端口用于展示。TCP 除 `LISTEN` 外还保留 `ESTABLISHED`、`CLOSE_WAIT`、`TIME_WAIT` 等可见状态，以便区分服务监听、活动连接和内核管理的连接状态。没有所属进程的记录也会保留其状态，不会给它虚构一个可终止的 PID。

查询结果是快照。绑定地址、地址族、套接字选项和并发活动都会影响重新绑定是否成功；尚未进入端口表的套接字也可能不可见。因此，“没有匹配端点”表示在本次扫描范围内没有观察到记录。

## 监听列表

```bash
portsnap --list
```

此模式用于查看服务入口，不需要指定端口。TCP 只显示 `LISTEN`；UDP 没有 TCP 的监听状态，显示当前可见的绑定端点，包括已指定对端的 UDP 套接字。

`--list` 与显式端口参数互斥，两种模式对应不同查询目的，不能同时指定。

## 协议与地址族过滤

```bash
portsnap 8080 --tcp -4
portsnap --list --udp --ipv6
portsnap 8080 --tcp --details --kill
```

`--tcp` 与 `--udp` 互斥；`-4` / `--ipv4` 与 `-6` / `--ipv6` 互斥。未指定某组时包含该组的两种类型，同时指定冲突选项会在扫描前报参数错误。过滤本身不构成查询模式，仍需指定端口或 `--list`。

地址族按套接字的原生类型判断。IPv4 映射 IPv6 地址（例如 `::ffff:127.0.0.1`）属于 IPv6，包含在 `-6` 查询中。双栈 IPv6 监听器也可能接受 IPv4 连接，因此 `-4` 的空结果不能证明某个 IPv4 地址可以绑定。

过滤条件尽早限制采集范围；未请求的协议表失败不影响当前查询完整性。结果整理再次校验条件，保证跨平台语义一致。终止操作的目标选择、确认后的归属复查和最终扫描使用同一组条件；被排除的端点不会单独成为终止理由，但终止选中进程仍会关闭它持有的其他端点。

## 进程详情

```bash
portsnap 8080 --details
portsnap --list --tcp --details --json
```

仅靠进程名无法区分多个运行实例。`--details` 增加可执行文件路径、启动参数、运行用户、父 PID 和 UTC 启动时间，用于判断占用来自哪个程序、如何启动及由谁运行。参数使用数组，保留空参数和带空格的参数；不解析或输出环境变量。

详情需要额外系统访问，且命令行可能包含敏感参数，因此默认查询只读取原有名称和身份信息。详情只为匹配端点的所属进程采集，并按 PID 与原生身份缓存；文本为共享多个端点的同一进程展示一次详情，JSON 将详情附在各 owner 中。

采集前后核验身份。缺少可靠身份、进程退出或身份变化时，丢弃无法验证的详情并给出 `identity` 字段诊断。各业务字段独立处理：路径不可读不妨碍返回用户或父 PID；任何请求字段缺失都会使报告不完整，并记录字段与原因。详情失败不删除已观察到的端点，也不代替终止前的身份和归属复查。

Unix 用户信息使用有效 UID，Windows 使用主进程令牌 SID，账户名称不可解析时仍保留 ID。Windows 参数按 `CommandLineToArgvW` 约定从系统命令行还原，可能与应用自定义解析结果不同。启动时间用于展示，和终止核验使用的原生启动标识分开；Linux 展示时间受系统启动时间与时钟 tick 精度限制。父 PID 是采集时的系统记录，不表示父进程仍然存活。

## 多进程归属与完整性

父子进程、worker 或其他共享机制可能让多个进程持有同一个端点。报告保留所属进程数组，文本视图为每个已知进程显示一行。同一个进程持有多个匹配端点时，终止交互只处理该进程一次。

端点可见性和进程元数据可见性并不相同。例如，Linux 可能允许读取端口表，却不允许读取其他用户的 FD。此时仍可报告端口、协议和状态，同时注明归属不可获取。

| 情况 | 输出行为 |
| --- | --- |
| 查询完整且没有匹配端点 | 返回完整的空报告 |
| 请求范围内的协议表不可读取或解析，或请求的进程信息不可获取 | 保留可用条目，添加诊断，标记报告不完整 |
| 全部请求的端点数据源失败，或 macOS 的 lsof 字段输出整体无效 | 返回操作错误 |
| TCP 状态由内核管理、没有用户进程 FD | 保留记录，并标记归属不适用 |

完整性按当前操作系统接口和可见范围解释。Linux 受网络命名空间及 procfs 权限影响；Windows 受 IP Helper 提供的字段范围影响；macOS 普通用户运行 `lsof` 时可能缺少其他用户的记录。具体采集方式见 [架构设计](architecture.md)。

## 终端展示与 JSON

文本表格包含 `PROTO`、`LOCAL ADDRESS`、`REMOTE ADDRESS`、`STATE`、`PID` 和 `PROCESS`。地址列根据内容调整宽度；IPv6 加方括号并保留已知作用域，例如 `[fe80::1%en0]:8080`。没有远程端点时显示 `-`。

TCP 显示实际状态；UDP 文本状态为 `BOUND`，JSON 中的 `state` 为 `null`。无法获取进程信息和没有用户进程归属是不同情况，分别显示对应说明。进程名和诊断中的控制字符会被转义，避免它们改变终端显示。

```bash
portsnap --list --json
```

JSON 报告让脚本直接读取端点和所属进程，不必解析人类可读表格。stdout 输出数据，stderr 输出诊断；`--json` 与交互终止互斥，防止确认提示混入数据。完整字段说明见 [JSON 接口](json.md)。

每条报告诊断包含稳定 `code`、来源 `source` 和可读 `message`。脚本可通过 `permission_denied`、`process_changed`、`source_unavailable` 等代码区分原因，不需要匹配会变化的错误文本。多个进程的同类详情问题在报告层汇总，owner 内仍保留各字段原因；程序应兼容未来新增代码，并结合 `complete` 和退出码处理结果。

## 交互式终止

```bash
portsnap 8080 --kill
portsnap 8080 --kill --force --timeout 5
```

此功能终止整个进程，不只是关闭某一个套接字。进程的其他端口和正在执行的工作也会受到影响。目标来自首次扫描的已知所属进程；操作期间新出现的所属进程只展示，不自动加入终止列表。

终止按以下顺序执行：

1. 汇总首次扫描的所属进程，按 PID 去重；身份冲突时拒绝继续。
2. 取得对应进程的稳定系统引用并核验身份，然后提示用户确认。
3. 用户回答 `y` 或 `yes` 后，再次扫描指定端口，检查同一身份是否仍拥有匹配端点。
4. 归属可核验时请求终止，并在超时期限内等待进程退出。
5. 完成已确认目标的处理后再次扫描，显示剩余端点及其当前归属。

默认回答为否。输入结束或读取失败会停止后续交互并返回失败，不会把缺少回答当作确认。PID 0、PID 1、工具自身，以及缺少可核验身份的进程不能作为终止目标。

用户可能在确认提示前停留较长时间，原进程也可能在此期间退出。稳定引用用于避免 PID 被复用后指向另一个进程；归属复查则用于避免终止已经不再持有目标端口的进程。如果复查不完整且无法确认归属，不发送终止请求。

### 平台行为

| 平台 | 稳定引用 | 终止方式与限制 |
| --- | --- | --- |
| Linux | pidfd | 默认 SIGTERM，`--force` 为 SIGKILL；需要内核支持，且 procfs PID 命名空间必须对应 |
| Windows | 进程句柄 | 使用 TerminateProcess 强制终止；需要对应进程访问权限 |
| macOS | Mach 任务端口 | 需要 `--force` 和系统授予的任务端口权限；使用 task_terminate |

macOS 的普通 PID 信号接口无法通过此处的稳定任务引用发送 SIGTERM，因此该平台只提供显式强制终止。无法取得稳定引用时，工具会报告原因，不回退到仅凭数字 PID 发送信号。

默认退出等待期限为每个进程 3 秒，`--timeout` 接受 1–60 秒。请求发送成功不等于已经退出；超过期限仍未确认退出时返回超时，不自动升级信号。

进程退出后，端点仍可能被其他共享进程持有，或以 `TIME_WAIT` 等内核状态存在。最终扫描保留这些情况，并让退出码反映仍有匹配端点，而不是只根据终止请求的返回值判断完成。
